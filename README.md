# GFQA reporting limit inference

Code accompanying **Reporting limits reshape chemical exceedance estimates and trends in a global freshwater archive**.

The analysis links reported concentration intervals to event-level threshold screening, station-year annual-mean screening, station-grouped model comparisons, conditional exceedance probabilities, paired within-station trends and follow-up measurement priorities. The repository contains analysis and plotting source, with one original monitoring vignette used by the workflow panel. Monitoring data, predictions, fitted models, result tables and manuscript files are not included.

## Data

Download **GFQA_v3.zip** yourself from the fixed [UNEP GEMS/Water Global Freshwater Quality Archive release](https://zenodo.org/records/18459694), DOI [10.5281/zenodo.18459694](https://doi.org/10.5281/zenodo.18459694). This is version v3, published 2 February 2026. Do not substitute another release or the all-versions DOI.

Place the unmodified ZIP at `inputs/GFQA_v3.zip`. Its size is 201,278,791 bytes, official MD5 is `00f3ea19ce529753977eb3aeb08fbc47`, and the verified local SHA-256 is `82b169dcbf5abf30066020b176b82474b23a2dec0a108a351045f31a6476e92a`. The preparation script checks both hashes. The original ZIP retains the supplied license information; keep it unchanged. Data licensing and attribution follow the original release, separately from this code repository.

Citation: Heinle, M.; Lisniak, D.; Saile, P. *UNEP GEMS/Water Global Freshwater Quality Archive*, version v3, Zenodo, 2026. DOI: 10.5281/zenodo.18459694.

Maps use auxiliary Natural Earth land and country geometries. The preparation script downloads pinned `v5.1.2` GeoJSON files from the [Natural Earth vector source repository](https://github.com/nvkelso/natural-earth-vector/tree/v5.1.2/geojson). They are not included here. Arial is used when installed; Matplotlib falls back to DejaVu Sans, which can slightly change text layout.

## Environment

The recorded analysis environment is Python 3.12.3 on Windows, using CPU training. Exact installed package versions are recorded in `environment.json` and the two requirements files. The CPU build recorded for PyTorch is `2.13.0+cpu`; the requirement uses its public version, `2.13.0`.

```bash
python -m pip install -r requirements-analysis.txt
# Add plotting dependencies when figures are needed:
python -m pip install -r requirements-figures.txt
python scripts/validate_release.py
python scripts/smoke_checks.py
```

This release has been checked by static source validation and small numerical utility checks. A new environment installation and the full training pipeline have not been rerun as part of preparing this repository. CPU library builds, package changes and parallel floating-point calculations can affect exact numerical reproduction. The study used approximately 50,000-event benchmark subsets selected with stations retained as groups; the runner explicitly sets `N_MAX=50000`, overriding the larger exploratory default in `s06`.

## Running the analysis

The runner prints its complete command plan by default. Training starts only when `--run` is supplied. Run commands from the repository root.

```bash
python scripts/run_pipeline.py                 # print every command; no analysis runs
python scripts/run_pipeline.py --stage prepare --run
python scripts/run_pipeline.py --stage profile --run
python scripts/run_pipeline.py --stage datasets --run
python scripts/run_pipeline.py --stage benchmark --run
python scripts/run_pipeline.py --stage crossfit --run
python scripts/run_pipeline.py --stage sensitivity --run
python scripts/run_pipeline.py --stage summaries --run
python scripts/run_pipeline.py --stage figures --run
```

`--stage all --run` executes the same sequence serially after the original ZIP has been downloaded. It converts 51.2 million measurement rows and trains many learners; it is a substantial analysis job, not a quick demonstration. Prepare enough memory and local disk for the converted archive and crossfit predictions. The figure stage consumes outputs from the earlier stages and regenerates six combined figures plus 37 independently drawn panels; it does not refit base learners. Optional SHAP output can be generated by running `s09_hidden_exceedance.py` without `--no-shap` after the primary reconstruction.

The original analyst script names and output columns are retained. Historical names containing `compliance`, `certified`, `artefact` or `retest` denote threshold-screening summaries, empirical bound eligibility, model-relative rule differences or follow-up priorities. They do not identify legal compliance decisions or measurements of stored historical samples. Reporting-limit comparisons use the logarithmic scale, with equality assigned below the strict exceedance boundary. The released `s05` fixes a linear back-transformation round-off issue at equal limits and describes the PFOA comparator as illustrative.

## Script map

| Scripts | Purpose |
|---|---|
| `s00`, `s01` | Verify the fixed ZIP, convert its three metadata files and stream measurement CSVs into Parquet |
| `s02`, `s03`, `s05` | Archive profile, unit/QC handling, event and target construction, threshold blind spots |
| `s04` | Optional initial feasibility benchmark; not part of the main reproduction plan |
| `s06`; `censml`, `learners`, `ensembles` | Station-grouped benchmark, interval likelihood utilities, 22 base learners and four ensembles |
| `s07`, `s08` | Multi-seed semi-synthetic censoring experiments and leave-country-out transfer |
| `s09` | Full-archive LGB-Tobit station crossfitting and conditional non-detect inference |
| `s10`, `assemble_figure_inputs` | Assemble numerical summaries and the two plot-specific input tables |
| `s11`, `s12` | Detected-value re-censoring checks and dissolved/hardness cadmium sensitivity |
| `s13`, `s14` | Within-station trends and whole-station bootstrap prevalence intervals |
| `s15`, `s17` | Distributional and reported-limit relabelling sensitivity |
| `s16` | Country and station follow-up measurement priorities |
| `s18` | Station-year annual-mean screening: half-limit means, interval bounds, censored-model means, exceedance probabilities and station-bootstrap intervals (`--ci`) |
| `generate_six_main_figures`, `method_workflow` and panel modules | Six current figures (one per Results section) and independent PNG/PDF panel exports |

Archive profile plots use all available target dates. Modelling and prevalence use events from 1980 onward. In `s16`, country-level triage and reporting-limit reductions use the full modelling period; station rankings use uncertain blind-spot events from 2015 onward. Expected hidden-exceedance counts are sums of conditional probabilities. In `s18`, station-years need at least four events; non-detects enter half-limit means at D/2, interval bounds at zero or D, and the censored-model mean at their truncated predictive expectation, and 200 joint draws give the probability that an annual mean exceeds its threshold. The conformal outputs report interval-identified empirical coverage bounds; dependence within stations and the crossfit construction constrain their interpretation.

## Outputs and logs

Scripts create local `data_processed/`, `results/`, `tables/` and `figures/` folders. The serial runner writes one UTF-8 log per command in `logs/`, including UTC time, command and exit code, and stops at the first failure. Inspect the `fails` object in each `bench_<target>_<setting>.json`: the historical benchmark can continue after a learner failure, so process exit success alone is insufficient. These inputs and generated folders are ignored by Git and must remain untracked. Scripts with top-level file reads should be executed as entry points, rather than imported for inspection.

`SOURCE_ADAPTATIONS.md` records portability and preparation changes. `summary_equivalence.json` records the elementwise comparison of the added summary assembler with the existing final summaries; it contains comparison diagnostics, not monitoring values. `CODE_MANIFEST.json` records release file hashes.
